## 1.1 นิยามที่ใช้ในคอร์สนี้

**Forward Deployed Engineer (FDE)** = วิศวกรที่ฝังตัวอยู่ในทีมลูกค้า เข้าใจสภาพแวดล้อมจริงของลูกค้า
แล้ว**สร้างและส่งมอบระบบ production** ที่แก้ปัญหาธุรกิจนั้นได้จริง โดยรับผิดชอบตั้งแต่ต้นจนจบ
— ไม่ใช่คนที่ทำแค่เดโมหรือสไลด์

### สามสิ่งที่ทำให้ FDE ไม่เหมือนใคร

| องค์ประกอบ | ความหมาย | ถ้าขาดสิ่งนี้จะเป็นอย่างไร |
|---|---|---|
| **Embedded** | อยู่ใน standup, Slack, codebase ของลูกค้า เห็นข้อจำกัดจริง | กลายเป็น consultant ที่เดา ไม่ใช่คนที่รู้ |
| **Builds** | เขียน production code เอง ไม่ใช่แค่แนะนำ | กลายเป็น Solutions Engineer / ที่ปรึกษา |
| **Owns outcome** | รับผิดชอบถึงระดับที่ "มีคนใช้จริงและ metric ขยับ" | กลายเป็น dev ที่ส่งงานแล้วจบ |

### FDE vs. ตำแหน่งข้างเคียง

| ตำแหน่ง | เขียน production code | ฝังตัว | Own outcome | รับผิดชอบ roadmap |
|---|---|---|---|---|
| **FDE** | ✅ | ✅ ระยะยาว | ✅ | ส่งเสียงกลับเข้า product ได้ |
| Solutions Engineer | ❌ (demo/config) | ช่วง sales | ❌ | ❌ |
| Solutions Architect | ❌ (PoC) | บางช่วง | ไม่เต็ม | ❌ |
| Technical Account Manager | ❌ | ✅ (relationship) | บางส่วน | ❌ |
| Forward Deployed **Strategist** | ❌ | ✅ | ✅ (business) | ✅ |
| ML / Applied Research | บางส่วน | ❌ | ❌ | ✅ (model) |

💡 **สำหรับคน non-dev:** บทบาท **Forward Deployed Strategist / Deployment Strategist** (มีที่ Palantir และบริษัท
enterprise อื่น) เป็นประตูที่สมจริงกว่า และใช้ทักษะเดียวกับ Module 10–12 ของคอร์สนี้ 100%
ถ้าคุณยังไม่พร้อมเขียนโค้ดเต็มตัว ให้พิจารณาเส้นนี้เป็น "parallel track"

## 1.2 งานจริงของ FDE ในหนึ่งสัปดาห์ (ตัวอย่างจริง)

| วัน | งาน | ทักษะ |
|---|---|---|
| จ. | ประชุมกับ ops manager หา bottleneck ของกระบวนการอนุมัติสินเชื่อ | discovery |
| อ. | เขียนสคริปต์ดึงข้อมูลจาก API ของลูกค้า, เจอว่า schema ไม่ตรงกับที่คุยไว้ | data + debugging |
| พ. | สร้าง RAG บน policy document + รัน eval ที่มี golden set 40 ข้อ | AI engineering |
| พฤ. | เจอว่า IT ไม่ยอมให้ส่งข้อมูลออกนอกประเทศ → ออกแบบ architecture ใหม่ | enterprise reality |
| ศ. | นำเสนอผู้บริหาร: ตัวเลขเวลาที่ประหยัด, ต้นทุน, ความเสี่ยง | exec comms |
| ทุกวัน | ตอบ Slack ลูกค้า, ปรับ prompt, เก็บ feedback | craft |

> สังเกตว่ามีแค่ 2 วันจาก 5 ที่เป็น "เขียนโค้ดล้วน" — นี่คือเหตุผลที่คน non-dev มีโอกาสจริง

## 1.3 สามเส้นทางสู่ FDE (เลือกตามพื้นหลังของคุณ)

```
เส้น A: Technical Builder          เส้น B: Domain Bridge ★แนะนำ       เส้น C: Strategy Track
──────────────────────────         ────────────────────────────       ─────────────────────────
มีพื้นฐานเทคนิคอยู่แล้ว              มี domain knowledge ลึก                มาจาก consulting/PM/ops
เรียน Phase 2–3 เร็วขึ้น            เรียน Phase 1–3 ให้แน่น               เรียน Phase 1 แบบเบา + Phase 4 ลึก
จุดต่าง = ความเร็ว                  จุดต่าง = เข้าใจธุรกิจจริง             จุดต่าง = ขาย/ขับเคลื่อนองค์กร
เป้า: FDE ที่ AI company           เป้า: FDE ที่ enterprise/vertical     เป้า: Forward Deployed Strategist
เวลา: 6–8 เดือน                     เวลา: 10–12 เดือน                     เวลา: 6–9 เดือน
```

**คำแนะนำของคอร์สนี้:** ถ้าคุณเป็น BA/analyst/consultant ให้เลือก **เส้น B** —
domain knowledge คือ moat ที่คนจบ CS ไม่มี และเป็นสิ่งที่ทำให้ FDE ระดับ expert มีค่ามาก

## 1.4 Self-Assessment (ทำก่อนเริ่ม — ใช้เวลา 45 นาที)

ให้คะแนน 1–5 ในแต่ละข้อ (1 = ไม่มีเลย, 5 = ทำงานได้เองโดยไม่ต้องหา help)

### Technical
- [ ] ใช้ terminal ได้ (cd, ls, grep, pipe) — ___
- [ ] อ่าน stack trace แล้วหาว่าพังตรงไหนได้ — ___
- [ ] เขียน Python ได้โดยไม่ต้องก๊อปจากที่อื่น — ___
- [ ] เข้าใจ HTTP method, status code, JSON — ___
- [ ] ใช้ Git (commit, branch, PR) ได้ — ___
- [ ] เขียน SQL JOIN ได้ — ___
- [ ] เคย deploy อะไรให้คนอื่นใช้ — ___

### AI
- [ ] อธิบายได้ว่า token, context window, temperature คืออะไร — ___
- [ ] เรียก LLM API จากโค้ดได้ — ___
- [ ] เข้าใจว่า RAG ทำงานอย่างไรและแก้ปัญหาอะไร — ___
- [ ] เคยเขียน eval / วัดผลระบบ AI — ___
- [ ] เข้าใจ prompt injection และวิธีป้องกัน — ___

### Craft (จุดแข็งของคุณ)
- [ ] ทำ requirement elicitation กับผู้ใช้จริงได้ — ___
- [ ] อธิบายเรื่องเทคนิคให้ผู้บริหารเข้าใจได้ — ___
- [ ] เข้าใจ P&L หรือ process ของธุรกิจอย่างน้อย 1 อุตสาหกรรม — ___
- [ ] จัดการ stakeholder ที่มีความเห็นขัดกันได้ — ___
- [ ] ขับเคลื่อนให้คนเปลี่ยนวิธีทำงานได้ — ___
- [ ] ประเมิน ROI ของโปรเจกต์ได้ — ___

### การอ่านผล
| คะแนนรวม Technical + AI | คะแนนรวม Craft | ควรทำอะไร |
|---|---|---|
| < 20 | > 20 | เรียน Phase 1–3 เต็มที่ ไม่ต้องกังวล Phase 4 (คุณมีแล้ว) |
| 20–35 | > 20 | เรียนตามปกติ แต่เร่ง Phase 2–3 |
| < 20 | < 20 | เริ่ม Phase 1 ก่อน แล้วค่อยๆ ไต่ — ใช้เวลา 12–15 เดือน |
| > 35 | < 20 | ระวัง! คุณจะเป็น "dev ที่ไม่ได้เป็น FDE" — ต้องทุ่ม Phase 4 เป็นพิเศษ |

## 1.5 เลือก Vertical ของคุณ (สำคัญที่สุดใน module นี้)

FDE ที่ดีจะไม่ใช่ generalist ลอย ๆ — เขาจะมี **อุตสาหกรรมที่เข้าใจจริง 1–2 อย่าง**

ให้เขียน 3 ตัวเลือกจากประสบการณ์จริงของคุณ แล้วให้คะแนน:

| Vertical | ทำไมคุณเข้าใจมัน (ประสบการณ์จริง) | มีบริษัทที่จ้าง FDE ในสายนี้ไหม | ข้อมูลหาได้ง่ายไหม |
|---|---|---|---|
| เช่น: การเงิน/สินเชื่อ | ทำงานสายสินเชื่อ 4 ปี | สูงมาก (fintech, bank) | ง่าย (มี public data) |
|  |  |  |  |
|  |  |  |  |

**เกณฑ์เลือก:** ต้องได้ ≥3 ทั้งสามคอลัมน์ → เลือกตัวที่สูงสุด
